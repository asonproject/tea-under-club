# おさがりシェアリング機能 GAS セットアップ手順

## 前提
Asanaタスク①（3シート作成）・②（Apps Scriptの器作成）が完了していること。

**実際のSHARED_SECRET・ADMIN_EMAIL・デプロイURLの値は、このファイルには書かない。**
このリポジトリはGitHub Pagesで公開される（`asonproject/tea-under-club`）ため、READMEに書くとそのまま外部に漏れる。実際の値は`.gitignore`対象の `gas/.env.local` に控えること。

## 手順

1. `Code.gs` の中身を、②で作ったApps Scriptエディタの `コード.gs` に全て貼り付けて保存する。

2. 関数選択のプルダウンで `setupSheets` を選び、▶実行ボタンを押す（初回は権限承認のダイアログが出るので許可する）。3シート（公開商品／提供者情報／申込み）が自動作成され、既定の空シートは削除される。

3. スクリプトプロパティを2つ設定する。
   - Apps Scriptエディタ左メニュー「プロジェクトの設定」→「スクリプト プロパティ」→「プロパティを追加」
   - `SHARED_SECRET`：ランダムな文字列（`openssl rand -hex 16` 等で生成。値は`.env.local`に控える）
   - `ADMIN_EMAIL`：申込み通知を受け取りたいメールアドレス（値は`.env.local`に控える）

4. デプロイする。
   - 右上「デプロイ」→「新しいデプロイ」
   - 種類の選択：ウェブアプリ
   - 実行するユーザー：自分
   - アクセスできるユーザー：**全員**（Cloudflare Workersがサーバー間で呼び出すため。SHARED_SECRETが実質的な認証になる）
   - デプロイ後に発行される「ウェブアプリのURL」を`.env.local`に控える

5. コードやスクリプトプロパティを更新した場合、URLを維持したいなら「デプロイを管理」→鉛筆アイコン→バージョン：新バージョン→デプロイ、で更新する（「新しいデプロイ」を選ぶとURLが変わる）。

## 動作確認（デプロイ直後・任意）
ブラウザで以下にアクセスし、JSONが返ればOK（`YOUR_SECRET`は3で設定した値に置き換え）。

```
https://script.google.com/macros/s/xxxxx/exec?action=items&key=YOUR_SECRET
```

`公開商品`シートに1行もデータがない場合は `{"status":200,"items":[]}` が返る。まずは電動ベッドの行を1件手入力してから試すとわかりやすい。

## 注意
- `提供者情報`シートはこのAPIから一切参照していない（個人情報を公開APIに出さない設計）。申込みが来たら、`申込み`シートの商品IDを見て、担当者が`提供者情報`シートを手動で参照する運用。
- `SHARED_SECRET`は絶対にブラウザ側コード（HTML/JS）に書かない。Cloudflare Workersの環境変数にのみ置く。

## Airtable「おさがりシェアリング」ベースからの一括インポート

Airtable（BaaKeeテーブル、26件）の画像・商品情報を`公開商品`・`提供者情報`シートへ一括で取り込む機能。

### 事前準備：Airtable Personal Access Tokenの発行
1. [airtable.com/create/tokens](https://airtable.com/create/tokens) を開く
2. 「Create new token」→ 名前は任意（例：`gas-osagari-import`）
3. Scopes：`data.records:read` を追加
4. Access：対象ベースとして「おさがりシェアリング」を追加
5. Create token → 表示されたトークンをコピー（一度しか表示されません。値は`.env.local`に控える。このREADMEには書かない）

### 設定・実行
1. Apps Scriptエディタの「スクリプト プロパティ」に `AIRTABLE_TOKEN` を追加し、上記トークンを値として設定（値は`.env.local`にも控える）
2. `Code.gs`の内容を最新版に差し替えて保存
3. 関数選択のプルダウンで `importFromAirtable` を選び、▶実行ボタンを押す
4. 初回は権限承認ダイアログが出る（外部URLへのアクセス・Google Driveへのファイル作成が新たに必要になるため）。許可する
5. 実行完了後、「実行数」または「ログを表示」で `インポート完了: 新規◯件、スキップ◯件` のログを確認

### 仕様
- 商品IDは `at-<AirtableレコードID>` の形式。何度実行しても重複インポートされない（差分だけ取り込む設計）
- 画像はAirtableの添付ファイルURL（期限付き）をそのまま使わず、Google Driveへ複製してから直リンクを発行する
- Airtableの`いつまで猶予がありますか？`が「終了」の商品は、掲載状況を`掲載終了`にして「表示」チェックボックスもオフで取り込む
- `お名前`・`ご住所`・`連絡先`・`Email`は`提供者情報`シートにのみ書き込み、公開APIには一切含めない
- `ご住所`列が未入力プレースホルダー「提供先の住所を教えてください。」のままの行は、空欄として取り込む

## 表示/非表示チェックボック（`公開商品`シート列A）

`公開商品`シートの列Aに「表示」チェックボックスがあり、**これがオンの商品だけがWebページ（一覧・詳細）に表示される**。チェックを外すだけでその商品を即座に非公開にできる（行を消す必要はない）。

### 初回移行手順（既存シートに列Aを追加する。一度だけ実行）
1. `Code.gs`の内容を最新版に差し替えて保存
2. 関数選択のプルダウンで `addVisibilityColumn` を選び、▶実行ボタンを押す
3. 列Aに「表示」列が新設され、既存商品は元の「掲載状況」（受付中→チェック済み／掲載終了・非公開→チェックなし）から自動で初期状態が復元される
4. 既に「表示」列がある状態で実行した場合は何もせず終了する（何度実行しても安全）

### 運用
- 新しく手入力で商品を追加するときも、列Aにチェックボックスが自動で表示される（`setupSheets`実行時に広めに検証を適用済み）
- Airtableからのインポート（`importFromAirtable`）も、掲載状況が「掲載終了」でない限り自動でチェック済み（表示）の状態で取り込まれる
